# 친구 타임라인 제안 · 2026-10-24

상태: 시안 이후 사용자의 “이어서 진행” 요청으로 로컬 앱 구현과 migration·계약 검사를 추가했다. 운영 DB 적용·배포는 아직 수행하지 않았다.

## 화면 구성

친구 화면 안에 `타임라인`과 `친구별` 두 탭을 둔다. 기존 하단 메뉴 네 개는 유지한다. 타임라인은 여러 친구의 등록·최초 완료를 최신순으로 보여주고, 친구별 탭은 오늘 완료 수·남은 할 일·응원 여부를 빠르게 확인하는 용도로 정리한다. 친구 추가와 받은 요청은 화면 위의 보조 행동으로 남긴다.

타임라인은 전체 또는 특정 친구로 좁힐 수 있다. 각 행에는 프로필 캐릭터, 이름, 등록/완료 구분, 실제 활동 시각, 할 일 제목과 예정 날짜를 표시한다. 등록을 미완료 체크박스로 오해하지 않도록 사건 동사를 사용한다. 친구의 할 일을 직접 완료하는 컨트롤은 제공하지 않는다.

`오늘 응원하기`는 그 게시물에 대한 좋아요가 아니라 해당 친구의 오늘 하루 응원이다. 같은 친구의 여러 행에서 보냄 상태가 일치해야 한다. 과거 활동을 보고 오늘 응원할 때 과거 할 일을 자동 인용하지 않는다. 화면 이동과 필터 변경에도 기존 초안 확인·실패 후 입력 보존 규칙을 유지한다.

## 활동 규칙

- 등록은 `tasks.created_at` 기준으로 원본 할 일당 한 번만 표시한다. 반복 발생 건의 자동 생성이나 수정은 새 등록 사건이 아니다.
- 완료는 발생 건의 `first_completed_at` 기준이다. 완료 취소 시 완료 사건을 가리고 재완료해도 최초 시각을 유지해 피드 위로 반복 상승하지 않는다.
- 삭제된 할 일과 현재 연결되지 않은 소유자의 활동은 제외한다. 친구 연결 해제 직후 열려 있는 목록·상세 캐시도 비운다.
- 타임라인은 소식함 미읽음 수와 푸시를 늘리지 않는다. 소식은 기존 받은 응원·연결 요청·수락만 유지한다.
- 날짜 묶음은 보는 사람의 저장된 시간대, 할 일 예정 날짜는 소유자에게 저장된 날짜를 사용한다. 날짜와 활동 시각을 섞지 않는다.
- 첫 버전에서는 조회 완료·빈 목록·실패·추가 조회 실패를 구분하고 명시적인 새로고침을 제공한다. 실시간 전달이 보장된다는 표현은 사용하지 않는다.

## 구현 경계

기존 `list_social_activity`는 친구 완료 기록 페이지에서 사용하므로 변경하지 않는다. 별도 `list_friend_timeline` 보안 읽기 RPC에서 원본 할 일 등록과 발생 건 최초 완료를 합쳐 정렬한다. 새 기록 테이블이나 보상 쓰기는 필요하지 않다. 각 조회에서 인증과 현재 친구 연결을 다시 확인하고 명시적 권한을 적용한다.

출력 제안: `items: [{ kind, eventId, occurredAt, owner: { id, displayName, avatarKey }, task: { id, title, dueDate }, occurrenceId? }]`, `nextCursor: { occurredAt, kind, eventId } | null`. 동일 시각에도 중복·누락이 없도록 시각/종류/ID를 모두 페이지 경계로 사용한다. 제목은 현재 활성 할 일의 내용이며 과거 원문 스냅샷을 제공한다고 표현하지 않는다.

신규 순서형 migration, SQL 계약, 읽기 응답 검증, 데모 혼합 활동, 친구 화면 상태와 UI를 함께 추가한다. 공통 오류는 AppError 계약을 따른다. 개인 이메일·펫 그림·기기 토큰은 출력에 포함하지 않는다.

## 검증할 것

비로그인·비연결 조회 거부, 친구 연결 해제 후 가림, 동일 시각의 등록/완료 페이지 경계, 반복 생성 제외, 취소/재완료 정렬 유지, 삭제 후 가림, 실패와 추가 조회 재시도, 계정 전환의 늦은 응답 차단을 검사한다. 모바일 360/390/430px와 데스크톱에서 긴 이름·80자 제목·확대 글자·응원 초안·뒤로가기·초점 복귀를 확인한다. 실제 DB 실행과 데모 검증을 구분한다.
