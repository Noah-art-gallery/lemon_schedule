# 현재 확인된 문제

## 로컬 Supabase 런타임 부재

Docker/Supabase 로컬 서비스가 실행되지 않는 환경에서는 `supabase test db`가 데이터베이스 연결 전에 실패한다. 2026-10-03 전용 클라우드 프로젝트에서 migration 적용과 pgTAP 보안 16개·행동 103개는 실제 통과했다. 로컬 reset과 빈 DB 재적용은 별도 미검증이므로 Docker가 가능한 환경에서 다시 실행해야 한다.

## 네이티브 빌드·실기기 푸시 미검증

2026-10-03 이 Windows PC에서 Android Studio·SDK·ADB 설치 파일과 PATH의 Java를 확인했다. 그러나 SDK 패키지·JDK 버전 호환성, Gradle 네이티브 빌드와 실제 기기 설치는 미검증이다. Firebase Android 설정과 서버 자격은 등록했지만 실제 알림 수신·탭 이동 증거는 남아 있지 않다. Android 기기를 연결해 권한 허용·거부·토큰 교체를 확인해야 한다. iOS APNs·서명 자격은 별도로 준비해야 한다.

전용 Supabase 프로젝트 연결·8개 migration·실제 연결 환경의 Android/iOS `cap sync`는 완료했다. 서버 발송 함수 v1도 배포했다. 웹훅 비밀값 미설정 상태에서는 POST가 `503 NOT_CONFIGURED`였으며, 비밀값 등록 후에는 헤더 없는 요청이 401로 차단되고 올바른 헤더와 잘못된 이벤트는 400 `INVALID_EVENT`로 거부되는 것을 확인했다. 2026-10-03 Android Firebase 설정 파일 저장과 서버 FCM 자격 3개 등록·원격 해시 확인은 완료했다. 웹훅 비밀값과 Vault 설정, INSERT 전용 DB 트리거도 연결해 실제 HTTP 200 응답을 확인했다. APNs 자격과 실제 발송·실기기 전달은 미검증이다. 이 상태에서는 친구가 앱을 닫았을 때 휴대폰 알림이 실제 도착한다고 보장할 수 없다. iOS 서버 자격을 준비하고 두 실기기의 최초 완료·재완료·로그아웃 사례를 검사해야 한다.

강제로 세션이 만료된 기기에는 예전 계정의 서버 토큰 행이 남을 수 있다. 앱은 세션 종료·다른 계정 로그인 전과 서버 등록 실패 시 OS 푸시 등록을 해제하지만, 기존 서버 행과 새 계정의 같은 APNs/FCM 토큰이 충돌할 수 있다. 두 계정·실기기의 재등록·전달 결과를 아직 확인하지 않아 푸시는 출시 차단 상태다. 검증 환경에서 이전 계정 행 정리 또는 서버 측 안전한 토큰 소유권 이전을 설계·검증해야 한다.
