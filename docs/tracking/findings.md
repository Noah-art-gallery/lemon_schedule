# 현재 확인된 문제

## 로컬 Supabase 런타임 부재

Docker/Supabase 로컬 서비스가 실행되지 않는 환경에서는 `supabase test db`가 데이터베이스 연결 전에 실패한다. 이 상태에서 pgTAP 통과를 주장하면 보안 계약을 검증하지 않은 채 배포할 위험이 있다. 현재는 정적 SQL 계약 검사만 통과로 기록하고, Docker가 가능한 환경에서 migration reset과 행동 검사를 다시 실행해야 한다.

## 모바일 푸시 자격 미설정

Windows 개발 환경에는 Android SDK와 APNs 서명 자격이 보장되지 않는다. 따라서 기기 토큰 등록 코드는 준비했지만 실제 알림 수신·탭 이동 증거는 남아 있지 않다. Android SDK/Java와 Firebase, iOS APNs 자격을 준비한 뒤 실기기에서 권한 허용·거부·토큰 교체를 확인해야 한다.

Android/iOS 네이티브 프로젝트 생성과 `cap sync`는 통과했다. 서버 발송 함수와 중복 시도 장부도 저장소에 추가했지만, 현재 연결된 Supabase 계정에는 이 앱 전용 프로젝트가 없고 Firebase/APNs 자격도 없어 웹훅 배포·서버 런타임·실기기 전달은 미검증이다. 이 상태에서는 친구가 앱을 닫았을 때 휴대폰 알림이 실제 도착한다고 보장할 수 없다. 이 앱 전용 프로젝트와 Firebase/APNs 자격을 준비한 뒤 서버 비밀값을 등록하고 두 실기기의 최초 완료·재완료·로그아웃 사례를 검사해야 한다.

강제로 세션이 만료된 기기에는 예전 계정의 서버 토큰 행이 남을 수 있다. 앱은 세션 종료·다른 계정 로그인 전과 서버 등록 실패 시 OS 푸시 등록을 해제하지만, 기존 서버 행과 새 계정의 같은 APNs/FCM 토큰이 충돌할 수 있다. 실제 프로젝트와 두 계정·실기기가 없어서 재등록·전달 결과를 확인할 수 없으므로 푸시는 출시 차단 상태다. 검증 환경에서 이전 계정 행 정리 또는 서버 측 안전한 토큰 소유권 이전을 설계·검증해야 한다.
