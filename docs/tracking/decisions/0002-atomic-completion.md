# 완료·보상·알림의 서버 원자화

## 배경

완료 체크는 친구 알림과 펫 성장의 공통 원인이다. 클라이언트가 상태 저장·포인트 증가·알림 생성을 따로 호출하면 중복 완료나 부분 성공이 생긴다.

## 선택

소유자 인증, 발생 건 잠금, 완료 상태 변경, 최초 완료 사건, 포인트 증가, 연결 사용자별 앱 알림을 하나의 보안 RPC에서 처리하고 유일 제약으로 중복을 막는다. 외부 휴대폰 전송은 이 기록 뒤에 시도한다.

## 대안

클라이언트에서 세 요청을 순서대로 보내면 UI는 단순해 보이지만 동시 기기와 네트워크 재시도에서 보상 중복을 막을 수 없다. 별도 메시지 큐는 안정성은 높일 수 있으나 MVP 운영 복잡도에 비해 이득이 작다.

## 결과

완료 RPC가 반환하는 최초 완료 여부와 보상 여부가 축하 UI의 기준이 된다. 푸시 전송 실패는 앱 안 알림과 포인트를 되돌리지 않으며, 후속 서버 발송 작업을 추가할 수 있다.
