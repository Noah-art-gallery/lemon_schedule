# 하루 응원과 화면 위계

기록일: 2026-10-13

## 배경과 사용자 피드백

응원 작성과 날짜·버튼·카드의 강조가 경쟁해 누구의 어느 하루를 보고 있는지, 응원을 실제로 보냈는지 분명하지 않았다. 사용자는 마이루틴 등의 잘 구조화된 디자인 패턴을 참고하되 화면을 복제하라는 뜻은 아니라고 명확히 했다. 이번 수정 후에는 이전보다 훨씬 나아졌다고 평가하고 재사용할 내용을 기록해 달라고 요청했다.

이는 이번 개선 방향에 대한 긍정적 피드백이다. 개별 수정이 각각 효과를 냈다는 사용자 검증이나 전체 디자인 최종 승인으로 확대하지 않는다.

## 유지할 설계 원칙

- 참고 화면에서는 정보 묶음, 날짜의 소속, 반복 행의 정렬, 주요·보조 행동의 위계를 읽는다. 레몬의 목적과 데이터에 맞게 적용하고 기존 색상·캐릭터를 유지한다.
- 친구 이름과 날짜, 오늘 할 일, 응원 상태 순서로 읽히게 한다. 날짜는 관련 사람·내용 가까이에 두고 같은 종류의 정보는 같은 시작선에 배치한다.
- 친구 추가·받은 요청·응원 진입을 모두 주요 버튼처럼 강조하지 않는다. 글자 크기·간격·색·영역 분리로 우선순위를 만들고 불필요한 큰 카드와 테두리를 줄인다.
- 목록은 현황과 결과를 보여 주고 작성은 별도 패널에서 한다. 스티커 선택은 초안이며 명시적인 전송 뒤 목록에 보냄 상태와 내용이 남는다. 수정은 같은 자리를 갱신한다.
- 투두 하나하나가 댓글이 쌓이는 게시글처럼 되지 않게 한다. 수신자 현지 날짜 기준 작성자당 하루 응원 한 건을 두고, 필요하면 오늘 할 일을 선택적으로 인용한다.
- 그림은 일정한 정사각 크기·여백을 가진 투명 2D 리소스로 사용한다. 프로필·응원·기본 레몬의 그림체를 통일하고 DB에는 기존 리소스 키를 저장한다. 홍보 배너 시안과 앱 내부용 스프라이트는 별도 산출물이다.

## 다음 작업에서 확인할 것

실제 크기에서 목록 → 작성 → 전송 결과 → 수정·취소까지 이어서 본다. 전송됐는지, 무엇을 눌러야 하는지, 어느 날짜의 내용인지 문구를 덧붙이지 않아도 분명한지 확인한다. 좁은 화면·긴 이름·긴 제목·초점 복귀도 함께 본다.

이번에는 공식 스토어 스크린샷을 참고했고 해당 앱 내부 조작까지 확인하지 않았다. 브라우저 데모와 자동 검사 통과도 실제 계정·휴대폰 검증과 구분한다. 겹친 작성·확인 패널이 함께 닫힐 때 배경 잠금이 남는 오류는 실제 조작에서 발견했다. 따라서 열린 화면의 캡처뿐 아니라 닫은 뒤 다음 행동이 가능한지도 검사한다.
