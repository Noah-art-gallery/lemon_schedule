# 정적 Next.js와 Capacitor 경계

## 배경

MVP는 웹과 앱스토어용 앱을 동시에 준비해야 하지만 별도 서버를 만들 여유가 없다. 화면과 데이터 흐름을 하나로 유지해야 기능 검증이 중복되지 않는다.

## 선택

Next.js App Router를 정적 export하고 `out`을 Capacitor WebView가 읽도록 한다. 인증·데이터·보안 RPC는 Supabase에 두고 클라이언트에 서비스 키를 포함하지 않는다.

## 대안

Next.js 서버 런타임과 별도 API를 추가하면 서버 전용 로직은 편해지지만 정적 앱과 배포 대상이 두 갈래가 되고 MVP 운영 범위가 커진다. 오프라인 동기화도 지금은 핵심 완료 흐름을 검증하기보다 충돌 정책을 먼저 요구하므로 선택하지 않았다.

## 결과

브라우저와 앱은 같은 기능 서비스를 사용하지만 서버 전용 동작은 Supabase RPC로 제한된다. 서버 API 라우트를 추가할 때는 정적 export와 Capacitor 동기화가 깨지지 않는지 먼저 확인해야 한다.
