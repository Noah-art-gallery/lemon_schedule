# 시스템 구성

브라우저 또는 Capacitor WebView가 정적 Next.js 화면을 열고, 기능 서비스가 Supabase Auth·Postgres·Storage에 요청한다. 클라이언트는 공개 키와 사용자 세션만 사용하며 서버 전용 런타임을 요구하지 않는다. 정적 출력 `out`은 웹과 Android/iOS가 공유한다.

할 일 화면은 오늘·예정·기록, 친구 화면은 사람별 오늘 현황·하루 응원과 친구별 일정, 소식은 직접 받은 응원과 연결 요청·수락으로 구분한다. 할 일 제목과 기존 응원 소식은 발생 건 상세를, 하루 응원 소식은 정확한 하루 응원 패널을 연다. 완료는 행에서 독립적으로 처리하고, 기존 발생 건 응원은 공통 읽기 컴포넌트를, 친구별 오늘 카드는 `DailyFriendCard`를 재사용한다. 카드의 응원 요약은 목록 조회 결과를 사용하고 펼침 또는 작성 진입 시 해당 발생 건 상세를 조회한다. 공통 패널은 모바일에서 내용 높이에 맞추되 화면 높이의 94%를 넘지 않고 데스크톱에서는 측면에 배치하며 배경 입력을 잠근다.

완료 RPC는 발생 건 상태·최초 완료 사건·포인트·기존 완료 이벤트를 원자적으로 저장한다. 친구 활동은 현재 조회 권한이 있는 완료 발생 건을 읽고, 소식 조회와 배지는 직접 소식 세 종류만 읽는다. 완료 이벤트를 삭제하거나 보상 트랜잭션에서 제거하지 않는다.

`tasks`가 발생 건과 공통 상세, `connections`가 승인된 공유 범위와 친구 삭제, `encouragements`가 하루 응원 입력·수정·취소 및 기존 발생 건 응원 기록을 담당한다. `daily_encouragements`는 수신자·작성자·수신자 기준 날짜의 UNIQUE 제약으로 하루 한 건을 보장하고 선택 발생 건을 인용한다. 친구 삭제의 서버 성공은 목록 재조회보다 먼저 공유 캐시와 응원 초안을 제거하며, 재조회 실패는 이미 끝난 관계를 복원하지 않는다. `notifications`는 직접 소식 조회와 정확한 대상 열람 후 읽음 처리를 담당한다. 프로필·펫의 데모 데이터는 할 일 데모와 같은 메모리 상태를 사용하며 실제 Supabase 데이터와 섞지 않는다.

프로필 서비스는 선택한 캐릭터 키를 공개 프로필 행에 저장하고 친구·활동·상세·응원·소식 조회로 전달한다. 프로필·응원·로고·기본 펫은 공통 `CharacterSprite`와 로컬 투명 PNG atlas를 사용한다. 그림별 원본 좌표를 공통 정사각 viewport에 비율을 유지해 정렬하며 이미지 업로드나 외부 이미지 요청은 필요하지 않다. 개인 펫의 비공개 그림 경로와 공개 프로필 캐릭터는 저장·조회 경계를 공유하지 않는다.

펫 그림은 비공개 Storage에 새 버전으로 올린 뒤 소유자의 그림 경로를 바꾼다. 경로 갱신이 실패해도 이전 그림이 유지된다. 휴대폰 발송은 알림 INSERT 웹훅 뒤에 독립적으로 수행한다. 함수는 직접 소식 종류와 현재 대상 권한을 다시 검사하고 기기별 발송 시도를 선점한다. 공급자 실패는 이미 저장된 사용자 행동을 되돌리지 않는다.

처리 결과는 공통 `useFeedback`·`FeedbackToast`, 조회 대기는 `LoadingIndicator`, 전송 대기는 기존 `Button.loading`으로 표시한다. 화면 전체에서 최신 토스트 하나만 유지하고 열린 패널 내부로 portal하여 배경 잠금과 초점 순환을 보존한다. 완료 모션은 성공 응답 뒤에만 시작하며 최초 완료와 보상 지급이 모두 확인된 경우에만 성장 수치를 표시한다. 반복 완료·취소는 포인트 증가로 표현하지 않는다. 실패와 입력 복구 안내는 해당 작업 위치에 남긴다.
